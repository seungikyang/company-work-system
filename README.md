## 빠른 실행

**1. 터미널에서 서버를 실행합니다.** 아래 두 줄을 순서대로 복사해 실행하고, 이 터미널은 열어 둡니다.

```bash
cd "/Users/seoowoo/Documents/company-work-system"
./scripts/assert_repo_root.sh && python3 scripts/serve_workbook.py
```

**2. 브라우저 주소창에 원하는 화면의 주소를 입력합니다.** 메인 프로그램과 문제집은 같은 서버를 사용하므로 서버는 한 번만 실행합니다.

| 실행할 화면 | 복사할 주소 |
|---|---|
| 메인 워크북 프로그램 | `http://127.0.0.1:4174/company-work-system/` |
| SW 기술 4지선다 문제집 · 2,000문항 | `http://127.0.0.1:4174/company-work-system/fundamentals.html` |
| SW 기술 4지선다 집중 퀴즈 · 10문제부터 시작 | `http://127.0.0.1:4174/company-work-system/quiz.html?bank=fundamentals&limit=10` |

**3. 문제를 풉니다.** SW 기술 문제집에서 보기 ①~④ 중 하나를 선택하고 `채점하고 해설 보기`를 누릅니다. `다음 25문항`으로 이동하거나, `풀이 상태`를 `오답 복습`으로 바꾼 뒤 `필터 적용`을 눌러 복습합니다. 한 문제씩 풀려면 위의 집중 퀴즈 주소를 사용합니다.

풀이 기록은 같은 브라우저와 접속 주소에 자동 저장됩니다. 기록을 파일로 보관하려면 메인 프로그램의 `학습 기록 내보내기`를 사용합니다. 종료할 때는 서버 터미널에서 `Ctrl+C`를 누릅니다. 다음 사용 때 서버를 다시 실행하면 저장한 기록으로 이어갈 수 있습니다.

아래에 준비물, 화면별 사용법, macOS에서 브라우저를 여는 명령과 실행 오류 해결 방법을 자세히 안내합니다.

## 프로그램 실행 방법

### 준비물

- JavaScript를 사용할 수 있는 최신 웹 브라우저
- 로컬 서버 실행용 Python 3
- 전체 저장소 파일: HTML 파일과 `practice/`, `scripts/` 폴더를 함께 유지합니다.

워크북과 객관식 문제집 실행에는 별도 패키지 설치나 빌드가 필요하지 않습니다. Node.js는 검증 스크립트를 실행할 때 사용합니다. Java·Gradle은 별도의 Spring Boot 실습 프로젝트를 구현할 때 사용합니다.

### 로컬 서버로 실행하기

1. 터미널을 엽니다. macOS에서는 `터미널` 앱을 실행합니다.
2. 다음 명령을 입력합니다. 현재 저장소의 실제 루트 경로이며, 다른 위치에 내려받았다면 첫 줄의 경로를 바꿉니다. 루트 확인이 성공해야 서버가 시작됩니다.

```bash
cd "/Users/seoowoo/Documents/company-work-system"
./scripts/assert_repo_root.sh && python3 scripts/serve_workbook.py
```

3. 아래 메시지가 표시되면 서버가 실행된 상태입니다. **이 터미널을 열어 둔 채** 브라우저 주소창에서 사용할 화면을 엽니다.

```text
취업 워크북 서버 실행: http://127.0.0.1:4174/company-work-system/
```

| 화면 | 브라우저에서 열 주소 | 용도 |
|---|---|---|
| 메인 프로그램 | [워크북 실행](http://127.0.0.1:4174/company-work-system/) | 목표·오늘 학습·진척도·답안·백업 관리 |
| 집중 퀴즈 | [선택형 웹 퀴즈 실행](http://127.0.0.1:4174/company-work-system/quiz.html) | 한 문제씩 선택·채점·해설 펼치기·오답 복습 |
| SW 기술 4지선다 문제집 | [2,000문항 문제집 실행](http://127.0.0.1:4174/company-work-system/fundamentals.html) | 보기 선택·채점·해설·오답 복습 |
| 코드 연결 문제집 | [40개 챕터 문제집 실행](http://127.0.0.1:4174/company-work-system/problems.html) | 4지선다 289문항·힌트·Starter·Hard·해설 연결 |

4. 메인 프로그램에서 목표 직무·마감일·하루 학습 시간을 입력하고, `오늘 볼 챕터`를 선택합니다. 표시된 4지선다 문제를 선택·채점하고 연결된 Starter·Hard·학습 문서를 엽니다.
5. 사용을 마치면 서버를 실행한 터미널에서 `Ctrl+C`를 눌러 종료합니다. 다음에 사용할 때 같은 명령으로 다시 시작하고 같은 주소로 접속합니다.

macOS에서 주소 입력 대신 명령으로 메인 화면을 열려면, 서버 터미널은 그대로 두고 **새 터미널 탭**에서 다음 명령을 실행합니다.

```bash
open "http://127.0.0.1:4174/company-work-system/"
```

서버는 저장소 폴더 이름을 주소에 사용합니다. 폴더명을 변경했다면 터미널에 출력된 주소를 기준으로 접속합니다.

### 서버 없이 빠르게 열기

파일 탐색기에서 [`index.html`](./index.html), [`fundamentals.html`](./fundamentals.html) 또는 [`quiz.html`](./quiz.html)을 브라우저로 엽니다. 객관식 화면은 HTML과 `practice/` 폴더의 CSS·JavaScript 파일을 함께 유지하면 실행됩니다. 문서 읽기·코드 연결 문제집은 파일을 요청하는 기능을 사용하므로 로컬 서버 방식으로 실행하세요. 파일로 열 때 저장이 제한될 수 있으므로 학습 기록을 계속 유지하려면 위 서버 방식과 일정한 주소를 사용합니다.

### 실행이 안 될 때

| 증상 | 확인할 내용 |
|---|---|
| `python3` 명령을 찾을 수 없음 | Python 3를 설치하고 새 터미널에서 `python3 --version`으로 확인합니다. |
| `Address already in use` 또는 포트 충돌 | 이미 워크북 서버가 켜져 있다면 위 주소로 접속합니다. 다른 프로그램이 4174 포트를 사용하면 충돌을 해소한 뒤 다시 실행합니다. |
| 연결할 수 없음 | 서버 터미널이 실행 중인지 확인하고 출력된 주소를 그대로 엽니다. |
| 404 화면 | `http://127.0.0.1:4174/` 뒤에 저장소 폴더 이름인 `company-work-system/`을 포함합니다. |
| 문제를 불러오지 못함 | `practice/quiz/` 폴더와 그 안의 CSS·JavaScript 파일이 모두 있는지 확인한 뒤 새로고침합니다. |
| 기록이 다른 화면과 다르게 보임 | 파일 실행과 서버 실행, 다른 브라우저·접속 주소는 저장 공간이 다릅니다. 메인 화면의 JSON 백업·복원으로 기록을 옮깁니다. |

## SW 기술 4지선다 문제집 실행 방법

### 문제집 서버 실행과 접속

1. 터미널에서 다음 명령을 실행합니다. 메인 프로그램의 서버가 이미 실행 중이라면 그대로 사용하고 2번으로 이동합니다.

```bash
cd "/Users/seoowoo/Documents/company-work-system"
./scripts/assert_repo_root.sh && python3 scripts/serve_workbook.py
```

2. 서버 터미널을 열어 둔 채, 원하는 풀이 방식의 주소를 브라우저에서 엽니다.

| 풀이 방식 | 실행 주소 | 사용하는 방법 |
|---|---|---|
| SW 기술 문제집 · 2,000문항 | [fundamentals.html 열기](http://127.0.0.1:4174/company-work-system/fundamentals.html) | 25문항씩 보며 보기 선택·채점·해설 확인 |
| SW 기술 집중 퀴즈 · 한 문제씩 | [기술 기본기 퀴즈 열기](http://127.0.0.1:4174/company-work-system/quiz.html?bank=fundamentals) | `기본기 10문제`로 시작하거나 10·20·50문제 범위 설정 |
| 코드 연결 문제집 · 289문항 | [problems.html 열기](http://127.0.0.1:4174/company-work-system/problems.html) | 40개 챕터의 문제와 Starter·Hard 코드 함께 학습 |

3. 보기 하나를 선택하고 `채점하고 해설 보기`를 누릅니다. 정답·오답과 해설이 표시됩니다. 집중 퀴즈에서 `선택 즉시 채점`을 켜면 보기를 고를 때 바로 채점합니다.
4. 오답 복습이나 `이 문제 다시 풀기`로 반복 학습합니다. 풀이 기록은 현재 브라우저에 자동 저장됩니다.

macOS에서는 서버가 실행된 상태에서 **새 터미널 탭**을 열고 다음 중 원하는 명령을 실행할 수도 있습니다.

```bash
# SW 기술 4지선다 2,000문항 문제집 열기
open "http://127.0.0.1:4174/company-work-system/fundamentals.html"

# SW 기술 문제를 한 문제씩 푸는 화면 열기
open "http://127.0.0.1:4174/company-work-system/quiz.html?bank=fundamentals"
```

### 한 문제씩 푸는 집중 퀴즈

[SW 기술 집중 퀴즈](http://127.0.0.1:4174/company-work-system/quiz.html?bank=fundamentals)는 한 문제씩 선택·채점·해설을 확인하는 반응형 웹 풀이 화면입니다. 이 주소는 `기술 기본기 · 2,000문항`을 선택한 상태로 열립니다. 서버 없이 `quiz.html`을 브라우저로 열 때는 `문제집`에서 `기술 기본기 · 2,000문항`을 선택한 뒤 학습을 시작하세요.

1. 코드 연결 289문항 또는 기술 기본기 2,000문항을 선택하고, 챕터·풀이 상태·키워드를 설정해 `이 범위로 학습하기`를 누릅니다.
2. A~D 보기 중 하나를 고르고 `채점하고 해설 보기`를 누릅니다. 정답과 내 선택을 표시하고 해설을 자동으로 펼칩니다. `해설 보기`로 접고 펼칠 수 있습니다.
3. `다음 문제`, `이전 문제`나 번호 버튼으로 이동합니다. 마지막 문제에서는 학습 결과와 미풀이 수를 확인하고 틀린 문제를 복습할 수 있습니다.
4. `이 문제 다시 풀기`로 해당 답안만 초기화합니다. 오답 복습 중에는 현재 목록을 유지하며, 범위 버튼을 다시 누르면 최신 상태로 갱신합니다.

상단의 `코드 연결 10문제`나 `기본기 10문제`로 짧게 시작할 수 있습니다. 학습 범위에서 한 번에 풀 문제 수를 10·20·50·전체 중 고르고, `선택 즉시 채점`을 켜면 보기를 누르는 즉시 정답과 해설이 열립니다. 기본기 문제는 해설의 `보기별로 이해하기`에서 다른 개념과 비교할 수 있습니다. 마지막 문제의 결과 화면에서 정답률을 확인하고 오답 복습이나 다음 미풀이 학습을 이어갑니다. 제한한 학습 범위의 시작 문항과 즉시 채점 설정도 주소에 유지됩니다.

문제 주석이 있는 코드 파일을 열면 **첫 화면부터 선택형 퀴즈가 표시됩니다.** `문제 + 학습 문서`에서 해당 파일의 문제를 풀고 아래에서 관련 코드도 읽을 수 있습니다. `관련 코드 보기`로 코드 위치에 바로 이동하며, `문제만 집중해서 풀기`로 풀이에 집중할 수도 있습니다. **그 파일에 실린 문항만** 선택·채점하고, `전체 범위로 전환`하면 같은 챕터의 나머지 문제도 풀 수 있습니다. 문제 주석이 없는 문서는 `4지선다 직접 풀기` 버튼으로 연결된 퀴즈를 엽니다. 초보자 기술 안내는 기본기 10문제로 연결됩니다. 보기 방식을 바꿔도 풀이가 유지되며, `큰 화면으로 풀기`로 집중 퀴즈를 따로 열 수 있습니다.

선택·채점 기록은 기존 문제집과 공유되고, 메인 화면의 JSON 백업에도 포함됩니다. 새로고침하면 주소에 표시된 문제로 돌아옵니다. Starter·Hard 문서 읽기 화면에는 해당 챕터 퀴즈로 이동하는 링크가 있습니다. 파일 실행과 서버 실행은 저장 공간이 다르므로 꾸준히 학습할 때는 같은 서버 주소를 사용하세요.

### 문제 선택·채점·복습

문제집을 열면 제목에 `기본기 4지선다 2,000제`가 표시됩니다. 40개 기술 단원에 각 50문항이 있으며, 한 페이지에 25문항씩 총 80페이지로 제공합니다.

1. 원하는 `사용 범위`, `기술 단원`, `유형`, `풀이 상태` 또는 `기술 검색`을 설정하고 `필터 적용`을 누릅니다. 처음에는 전체 2,000문항 중 첫 25문항이 표시됩니다.
2. 보기 ①~④ 중 하나를 선택하고 `채점하고 해설 보기`를 누릅니다. 정답 여부·정답·해설과 다른 보기의 의미를 확인합니다. 기술 식별 문항의 근거 표현은 채점 후 표시됩니다.
3. `다음 25문항` 또는 `이전 25문항`으로 페이지를 이동합니다. 오답만 다시 보려면 `풀이 상태`에서 `오답 복습`을 골라 `필터 적용`을 누릅니다.
4. `이 문제 다시 풀기`로 해당 문제의 선택·채점을 지우고 다시 풉니다. 선택과 채점 결과는 현재 브라우저에 자동 저장됩니다.

코드·설정 파일의 학습 질문을 풀려면 [코드 연결 4지선다 289제](http://127.0.0.1:4174/company-work-system/problems.html)를 엽니다. 같은 서버에서 보기 선택·채점·해설·재풀이를 사용할 수 있습니다.

| 구성 | 문항 수 | 다루는 기술 |
|---|---|---|
| 워크북 실제 구현 기술 | 600 | HTML, CSS, JavaScript, DOM, localStorage, JSON, fetch, Python HTTP 서버 등 |

## 학습 기록 백업과 복원

1. 메인 화면의 `학습 기록 내보내기`를 눌러 목표·오늘 학습·진척도·챕터 객관식과 현재 기술 개정판 기본기 풀이·이전 답안를 JSON 파일로 다운로드합니다.
2. 다른 브라우저나 접속 주소에서 메인 화면을 열고 `백업 파일 선택`으로 파일을 고릅니다.
3. 목표, 완료 챕터, 챕터 객관식·기본기 풀이와 이전 답안 개수를 확인한 뒤 `확인한 기록으로 복원`을 누릅니다. 파일 선택만으로 현재 기록이 바뀌지는 않습니다.

복원은 현재 기록을 파일 내용으로 교체하므로 필요한 기록은 먼저 내보냅니다. 객관식 기록이 미포함인 백업은 현재 객관식 풀이를 유지합니다. 이미 열린 객관식 화면은 복원 뒤 새로고침합니다. 지원하지 않는 버전, 잘못된 자료형·문항 ID와 5MB를 넘는 파일은 복원하지 않습니다. 손상된 브라우저 기록은 정상 항목만 읽고, 저장 실패 후에는 다음 입력 때 저장을 다시 시도합니다. 이전 개정판 기록과 다른 프로그램의 저장 항목은 백업·복원 대상이 아닙니다.

## 시작 순서

1. [HTML 워크북](./index.html)에 목표 직무, 첫 지원 마감일과 하루 학습 시간을 적습니다.
2. 5단계 로드맵에서 아직 완료하지 않은 첫 단계의 안내 문서를 엽니다.
3. 오늘 끝낼 FR ID, 챕터 하나와 완료 조건 한 문장을 정합니다.
4. 선택 챕터의 4지선다 문제에서 답을 고르고 채점·해설을 확인합니다. 필요하면 `1단계 힌트`를 엽니다.
5. 처음에는 Starter 또는 워크시트를 직접 풀고, 익숙해지면 Hard로 복습한 뒤 `정답 기준`과 Starter·상세 해설을 비교하고 빠진 내용을 보완합니다.
6. 표시된 결과물을 본인 프로젝트에 구현하고, 60분 체크 순서대로 실제 검증 명령과 실패·통과 결과를 기록합니다.
7. 답안 비교, 실행 결과물과 검증 증거가 모두 남았을 때만 완료로 체크하고 `다음 챕터`로 이동합니다.

한 번의 학습 세션은 `목표 선택 → 직접 풀이 → 실행 프로젝트 구현 → 검증 → 증거 기록` 순서로 끝냅니다.

## 챕터별 문제집 사용법

기초 개념을 먼저 확인하려면 [기본기 4지선다 2,000제](./fundamentals.html)를 풉니다. 기술 중심 개정판은 **워크북 실제 구현 기술 600문항**과 **백엔드 실습·확장 기술 1,400문항**으로 구성됩니다. 기술 단원 00~39에 각 50문항이 있으며, 기존 코드 연습의 챕터 번호와는 다른 목차입니다.

- 핵심 학습 항목 200개를 개념·적용 상황·구현 방법·오류 위험·검증 방법의 다섯 관점마다 설명 선택과 기술 식별 두 유형으로 연습합니다.
- HTML·CSS·JavaScript·DOM·localStorage·fetch·Python과 Java·Gradle·Spring MVC·JPA·Validation·세션·Thymeleaf·JUnit·MockMvc를 다룹니다.
- 같은 기술 단원의 인접 개념으로 구성한 네 보기 중 질문에 가장 직접적으로 해당하는 답 하나를 선택합니다.
- 모든 문항에 사용 범위·기술·근거 파일·확인할 코드 또는 주석 표현을 표시합니다. 백엔드는 완성 실행 앱이 아닌 실습 자료이며 Spring Security는 확장 미리보기로 구분합니다.
- `채점하고 해설 보기`를 누르면 정답, 설명, 다른 보기에 해당하는 개념과 연결된 학습 자료를 확인합니다.
- 사용 범위·기술 단원·유형·기술명으로 좁히거나 `미풀이`·`오답 복습`을 골라 `필터 적용`을 누릅니다. 한 페이지는 최대 25문항입니다.
- 선택과 채점 결과는 새로고침 후에도 현재 브라우저·접속 주소에 유지됩니다. `이 문제 다시 풀기`는 해당 문항의 선택과 채점만 지웁니다. 기존 워크북 기록과는 별도입니다.

면접 소개·포트폴리오 작성 등 기술 외 항목을 교체했습니다. 개정판은 새 저장 키를 사용하여 이전 문제집의 기록을 삭제하거나 다른 문제에 재사용하지 않습니다. 범위 점검과 기술별 출처는 [문항 기술 점검표](./practice/quiz/technology-audit.md)에 기록합니다.

객관식 문제집은 저장소의 `fundamentals.html`을 직접 열어도 작동합니다. 파일로 열 때 브라우저가 저장을 제한하면 안내가 표시되며, 일정한 주소에서 기록을 유지하려면 아래 로컬 서버 사용법을 따릅니다. 객관식을 맞힌 것만으로 챕터가 완료되지는 않으며 직접 구현과 테스트가 필요합니다.

코드 연결 문제집의 40개 챕터도 모두 4지선다입니다. 기존 학습 항목 148개·면접 질문 12개·공통 검증 질문 8개를 합친 168문항에 코드·설정 학습 질문 121문항을 추가한 **289문항**이며 기본기 2,000제와는 별도 문제집입니다.

1. 메인에서 오늘 볼 챕터를 고르거나 [코드 연결 4지선다 289제](./problems.html)를 엽니다.
2. 문항마다 보기 ①~④ 중 가장 적절한 답 하나를 고르고 `채점하고 해설 보기`를 누릅니다.
3. 정답 여부·정답 보기·해설을 확인하고, `이 문제 다시 풀기`로 해당 문항을 재풀이합니다.
4. 실제 Starter·Hard 파일로 이동해 배운 내용을 구현합니다. 챕터의 모든 문항을 채점하면 메인 현황의 `문제 채점 완료`에 반영되며, 실제 구현 완료는 별도로 표시합니다.

선택·채점은 메인 화면과 전체 문제집이 같은 저장 기록을 사용합니다. 새로고침과 챕터 이동 뒤에도 유지되며 이미 열린 다른 화면에도 변경이 반영됩니다. `새 학습 시작 · 오늘 기록만 비우기`는 풀이 기록을 보존합니다. 예전 서술형 답안은 새 선택지로 자동 변환하지 않고 메인의 `이전 학습 기록 보기`와 JSON 백업에 보존합니다. 이전 버전 1 백업도 복원할 수 있으며 새 백업은 챕터 객관식을 포함한 버전 2를 사용합니다.

원본 문항은 `practice/chapter-quiz-data.js`, 공통 채점은 `practice/chapter-quiz.js`, 화면 구성은 `practice/chapter-quiz-ui.js`에 있습니다. `practice/code-question-data.txt`의 추가 문항과 `practice/code-question-metadata.json`의 230개 원래 질문 대응표도 함께 사용합니다. `practice/problems.md`, 문서형 챕터 7개, Starter·Hard 코드·설정 파일 70개의 학습 문제는 같은 보기·정답·해설에서 생성됩니다. 수정 후 루트에서 `node scripts/generate_chapter_quiz.cjs`로 갱신하고 `node scripts/verify_chapter_quiz.cjs`로 289문항·기존 168문항 보존·코드 질문 230개 전수 대응·백업 호환을 확인합니다.

## 화면 탐색과 접근성

- 상단 메뉴에서 학습 단계로 이동하면 현재 메뉴가 표시되고 섹션 제목이 고정 헤더 아래에 보입니다. 모바일 메뉴는 한 줄로 유지되므로 좌우로 밀어 모든 항목을 확인합니다.
- 오늘 볼 챕터를 고른 뒤 표시되는 `00. 챕터명 문제로 이동` 버튼을 누르면 선택 문제로 이동하고 제목에 키보드 포커스가 놓입니다.
- 선택 문제 안의 이전·다음 버튼은 챕터 값, 문제, 위치와 포커스를 함께 갱신합니다. `전체 목차에서 이 챕터 보기`는 해당 교재 묶음을 열고 선택 행을 화면 가운데에 표시합니다.
- 모든 버튼은 Tab 키 포커스를 표시하며 운영체제의 동작 줄이기 설정이 켜져 있으면 부드러운 스크롤과 전환 효과를 줄입니다.

5. 다음 학습 때는 `새 학습 시작 · 오늘 기록만 비우기`를 눌러 목표·단계·완료 챕터를 유지한 채 오늘 기록만 초기화합니다.

## Orca에서 고정 URI로 열기

macOS의 Orca 앱에서 아래 명령을 저장소 루트에서 실행합니다.

```bash
./scripts/open_workbook_in_orca.sh
```

문제집은 항상 폴더 이름이 포함된 `http://127.0.0.1:4174/company-work-system/`로 열립니다. 실행 스크립트는 Orca 번들의 공식 CLI를 사용하며, 서버가 없으면 Orca 관리 터미널에서 시작하고 이미 정상 실행 중이면 같은 서버를 재사용합니다. 같은 워크트리의 브라우저 탭이 있으면 최신 화면으로 다시 이동하고 탭이 없을 때만 새로 만듭니다. 컴퓨터나 Orca를 다시 시작한 뒤에도 같은 명령을 실행하면 동일한 URI가 복원됩니다.

`4174` 포트를 다른 프로세스가 사용 중이면 해당 프로세스를 임의로 종료하지 않고 오류를 출력합니다. 이 경우 점유 프로세스를 확인해 충돌을 해소한 뒤 같은 명령을 다시 실행합니다. 로컬 서버는 `127.0.0.1`에만 연결되고 워크북 문서와 `practice/` 학습 파일만 제공하며, `.git`, `scripts`, 상위 경로와 디렉터리 목록은 공개하지 않습니다.

## 학습 문서 읽기 화면

메인 화면에서 `기능 워크북 열기`, `목표 워크시트 열기`, `테스트 챕터 열기`, Starter 또는 Hard 같은 학습 링크를 누르면 공통 읽기 화면으로 이동합니다. 이 화면은 Markdown과 Java 파일을 직접 다운로드하지 않고 문서 제목, 자동 목차와 구획으로 표시하며 메인 워크북 복귀와 인쇄 기능을 제공합니다.

직접 학습 파일 주소로 접근해도 로컬 서버가 공통 읽기 화면으로 연결합니다. 읽기 화면은 서버가 공개한 파일만 UTF-8 원문으로 불러오며 다른 경로나 상위 폴더는 요청할 수 없습니다.

`전체 문제`는 [코드 연결 문제집](./problems.html)으로 열립니다. 00~39 챕터마다 4지선다 문제 → 힌트 → 실제 코드 → 챕터 기술 해설 순서로 표시됩니다. 문항별 정답은 채점 후 표시되고, 챕터 기술 해설은 개별 또는 전체 펼치기로 읽습니다. 각 코드 버튼에는 저장소 상대 경로가 표시되며 같은 탭의 코드 읽기 화면으로 바로 이동합니다. 00장의 Gradle·YAML 설정 조각도 다른 코드와 같은 읽기 화면에서 확인할 수 있습니다.

## 워크북 화면 검증

HTML 목차나 학습 링크를 바꾼 뒤에는 저장소 루트에서 아래 명령을 실행합니다.

```bash
python3 scripts/verify_workbook.py
```

이 검사는 `index.html`, `problems.html`, `history.html`, `workbook-viewer.html`의 태그·중복 ID·로컬 링크, Markdown 상대 링크, JavaScript 구문과 DOM 연결, 6단계 목차·5단계 로드맵·40개 챕터·이전·다음 탐색·반응형 분기를 한 번에 확인합니다. 또한 Starter 40개와 Hard 33개 프로그램 폴더의 번호·대응 관계, 학습 파일 77개의 빈 파일·내부 목표 또는 챕터 계약·HTML 전수 연결, 문제 페이지의 40개 챕터·289개 객관식·힌트·기술 해설과 경로가 표시된 실제 파일 연결, 챕터별 선택·채점 저장 계약, 공통 문서 읽기 화면, Orca 고정 URI 서버와 실행 명령도 검사합니다. Python 3와 Node.js가 필요하며, 실패 메시지의 파일·링크·계약을 수정한 뒤 같은 명령이 통과할 때까지 다시 실행합니다.

위 검증에는 `fundamentals.html`의 구조·링크와 `node scripts/verify_fundamentals.cjs` 검사도 포함됩니다. 객관식 2,000문항의 고유 ID·지문, 기술 단원별 50문항, 보기 네 개·정답 하나, 200개 기술 항목의 근거 표현이 실제 파일에 존재하는지, 사용 범위별 문항 수, 정답 위치별 500문항, 풀이 통계·필터·저장 버전 분리·손상 데이터 처리와 JavaScript 구문을 확인합니다.

백업 관련 검사에는 `node scripts/verify_study_records.cjs`가 포함됩니다. 기록 왕복, 이전 저장 형식, 손상 항목 정리, 백업 버전·자료형 검사와 저장 실패 시 기존 기록 복구를 확인합니다.

워크북의 빈칸과 완료 체크는 아래 ID에 실제 링크가 연결될 때만 취업 증거로 인정합니다.

각 증거에는 코드 또는 문서 위치, 검증 명령과 결과, 커밋·PR, 설명할 핵심 선택, 마지막 확인일을 함께 기록합니다.
