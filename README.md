# Java 백엔드 취업 포트폴리오 워크북

사내 업무관리 시스템을 직접 설계하고 구현하면서 Java·Spring Boot 백엔드 취업에 필요한 결과물을 만드는 실습형 워크북입니다.

저장소를 내려받은 뒤 [`index.html`](./index.html)을 브라우저로 열면 목표 설정부터 오늘의 학습, 5단계 취업 준비, 00~39 전체 챕터까지 한 화면에서 순서대로 따라갈 수 있습니다. 입력한 목표와 완료 표시는 현재 브라우저에 자동 저장됩니다.

## 프로그램 정의

이 저장소 자체는 완성된 사내 업무관리 애플리케이션이 아니라 취업 준비를 돕는 **워크북 프로그램**입니다. 사내 업무관리 시스템은 워크북에서 반복해서 설계·구현·검증하는 실습 주제입니다.

| 구분 | 의미 |
|---|---|
| 워크북 프로그램 | 목표 설정, 오늘의 학습, 5단계·40개 챕터 진행 체크, 기술 문제, 구현 가이드, 정답 해설과 면접 준비를 제공하는 이 저장소 |
| 구현 대상 시스템 | 학습자가 별도 Spring Boot 프로젝트에서 완성할 직원·부서·휴가·공지·전자결재 시스템 |
| 최종 결과 | 실행 코드, 자동화 테스트, Git 기록, 포트폴리오 문서, 면접 답변 |

이 저장소의 목표는 빈칸 문제를 모두 푸는 것이 아닙니다. 아래 다섯 가지를 면접에서 설명할 수 있는 본인 프로젝트로 남기는 것이 최종 목표입니다.

- 실행 가능한 사내 업무관리 시스템
- 핵심 업무 규칙을 검증하는 테스트
- 구현 의도가 드러나는 커밋과 Pull Request
- README, ERD, API 명세, 트러블슈팅 문서
- 프로젝트 선택과 기술 설계를 설명하는 면접 답변

## 대상

- Java와 Spring Boot 기본 문법을 배운 뒤 포트폴리오 프로젝트가 필요한 사람
- CRUD를 넘어 승인·반려, 권한, 상태 전이, 트랜잭션을 연습하려는 신입·주니어 개발자
- SI·기업용 업무 시스템 백엔드 직무를 준비하는 사람

## 먼저 알아둘 점

`practice/starter/`와 `practice/hard/`의 Java 파일은 컴파일 가능한 완성 프로젝트가 아니라 핵심 로직을 직접 채우기 위한 코드 조각입니다. 정답을 복사해 제출하는 대신, 워크북에서 이해한 내용을 본인의 실행 가능한 Spring Boot 프로젝트에 다시 구현해야 합니다.

HTML 화면의 목표와 진행 상태는 로그인이나 외부 서버 없이 현재 브라우저의 저장 공간에만 보관됩니다. 브라우저 데이터를 지우거나 다른 기기에서 열면 자동으로 이어지지 않으므로, 제출할 코드·테스트·커밋과 상세 증거는 본인 프로젝트와 [취업 준비 통합 워크북](./practice/job-preparation-workbook.md)에 함께 남깁니다.

## 시작 순서

1. [HTML 워크북](./index.html)에 목표 직무, 첫 지원 마감일과 하루 학습 시간을 적습니다.
2. 5단계 로드맵에서 아직 완료하지 않은 첫 단계의 안내 문서를 엽니다.
3. 오늘 끝낼 FR ID, 챕터 하나와 완료 조건 한 문장을 정합니다.
4. 60분 체크 순서대로 직접 풀이, 구현, 테스트와 증거 기록을 마칩니다.
5. 실제 결과물이 남았을 때만 단계와 챕터를 완료로 체크하고 다음 행동으로 넘어갑니다.

한 번의 학습 세션은 `목표 선택 → 직접 풀이 → 실행 프로젝트 구현 → 검증 → 증거 기록` 순서로 끝냅니다.

## 취업 결과물로 연결되는 학습 흐름

| 단계 | 하는 일 | 남겨야 할 결과물 |
|---|---|---|
| 목표 설정 | 지원 직무와 채용 공고의 요구 역량 분석 | 목표 직무, 마감일, 역량 차이 |
| 설계 | 요구사항, ERD, API, 상태 전이 결정 | PRD 요약, ERD, API 초안 |
| 구현 | 기능별 Controller·Service·Repository·Entity 작성 | 실행 코드, 기능별 커밋 |
| 검증 | 성공·실패·권한·상태 전이 테스트 | 테스트 코드와 통과 명령 |
| 정리 | 선택 이유와 문제 해결 과정 기록 | README, 트러블슈팅, PR |
| 지원 | 프로젝트를 30초와 3분으로 설명 | 자기소개, 면접 카드, 지원 링크 |

## 취업 준비 5단계 통과 기준

다음 단계로 넘어가는 기준은 읽은 문서 수가 아니라 확인 가능한 산출물입니다.

| 단계 | 최소 통과 기준 | 다음 단계 |
|---|---|---|
| 준비 | 목표 직무·마감일을 적고 채용 공고 3개의 공통 요구 역량을 정리했다 | 설계 |
| 설계 | MVP 범위, ERD 초안, 핵심 API와 비즈니스 규칙을 결정했다 | 구현 |
| 구현 | 핵심 FR ID를 실행 프로젝트에 구현하고 기능별 커밋을 남겼다 | 검증 |
| 검증 | 성공·실패·권한·상태 전이 테스트와 실제 통과 명령을 기록했다 | 지원 |
| 지원 | README, 데모, 트러블슈팅, 30초·3분 설명과 공개 링크를 점검했다 | 지원 실행 |

단계별 상세 체크는 [취업 준비 통합 워크북](./practice/job-preparation-workbook.md)에서 관리합니다.

## 증거 ID 규칙

워크북의 빈칸과 완료 체크는 아래 ID에 실제 링크가 연결될 때만 취업 증거로 인정합니다.

| 종류 | 형식 | 예시 |
|---|---|---|
| 기능 | `E-{FR ID}` | `E-FR-LEAVE-005` |
| 문서·데모 | `E-DOC-{이름}` | `E-DOC-README`, `E-DOC-DEMO` |
| 트러블슈팅 | `E-TS-{번호}` | `E-TS-001` |
| 면접 답변 | `E-INT-{번호}` | `E-INT-001` |

각 증거에는 코드 또는 문서 위치, 검증 명령과 결과, 커밋·PR, 설명할 핵심 선택, 마지막 확인일을 함께 기록합니다.

## 기능 완료 기준

다음 항목을 모두 충족해야 기능 하나를 완료한 것으로 봅니다.

- [ ] 요구사항과 실패 조건을 본인 말로 설명했다.
- [ ] 실행 가능한 프로젝트에 직접 구현했다.
- [ ] 성공, 실패, 권한 또는 상태 전이 테스트를 작성했다.
- [ ] 테스트나 빌드 명령이 통과했다.
- [ ] 한 가지 의도로 설명 가능한 커밋을 남겼다.
- [ ] 설계 선택 또는 문제 해결 내용을 한 문단으로 기록했다.

빈칸의 답을 맞히거나 예제 코드를 읽은 것만으로는 완료가 아닙니다.

## 문서 유지 원칙

- 워크북 기능을 추가하거나 학습 흐름을 바꾸면 관련 안내 문서와 `history.html`을 함께 갱신합니다.
- 예시 코드와 PRD/TRD가 충돌하면 PRD/TRD를 기준으로 차이를 정리합니다.
- 구현하지 않은 기능은 완료된 포트폴리오 기능처럼 표현하지 않습니다.
- 테스트나 빌드를 실행하지 못했다면 그 이유를 결과 기록에 남깁니다.

## 최종 졸업 기준

- [ ] 프로젝트를 처음 받은 사람이 README만 보고 실행할 수 있다.
- [ ] 로그인, 직원·부서, 휴가, 공지, 전자결재의 핵심 흐름이 동작한다.
- [ ] 주요 비즈니스 규칙을 검증하는 자동화 테스트가 있다.
- [ ] ERD와 API 명세가 실제 코드와 일치한다.
- [ ] 본인이 해결한 트러블슈팅을 최소 3건 설명할 수 있다.
- [ ] 핵심 설계 질문 8개에 각각 30초 안으로 답할 수 있다.
- [ ] 이력서나 포트폴리오에서 저장소, 데모, 문서 링크를 바로 열 수 있다.
- [ ] 핵심 기능·문서·트러블슈팅·면접 답변이 증거 ID로 서로 연결되어 있다.

세부 진행 순서는 [학습 워크북 안내](./practice/README.md)를 따릅니다.
