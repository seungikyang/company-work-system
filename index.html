반드시 남길 다섯 가지

  • 본인의 실행 프로젝트에 작성한 코드 위치
  • 성공과 실패를 검증한 테스트 코드
  • 실제로 통과한 테스트 또는 빌드 명령
  • 한 가지 의도가 드러나는 커밋이나 PR
  • 선택 이유와 대안을 설명하는 면접 한 문장
증거 기록하기

막혔을 때 확인할 순서

  • 실제 오류 메시지와 실패한 입력을 먼저 기록합니다.
  • Starter에서 호출 순서와 계층 책임을 확인합니다.
  • PRD / TRD에서 요구사항과 업무 규칙을 확인합니다.
  • 마지막에 해설을 읽고 본인 말로 다시 설명합니다.
