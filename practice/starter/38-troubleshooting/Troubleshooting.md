## 4지선다 문제

### Q38-01. 중복 승인·부분 저장·Entity 노출·지연 로딩·동시 가입 문제를 다룰 때 알맞은 원칙은?

- ① 모든 문제를 CSS 수정으로 해결한다.
- ② 오류를 무시하고 성공 응답을 반환한다.
- ③ 코드 전체를 동시에 바꿔 원인 검증을 생략한다.
- ④ 각 문제의 재현과 원인을 확인하고 상태·원자성·응답·조회·DB 제약을 알맞은 경계에서 수정한다.

**정답:** ④

**해설:** 겉으로 비슷한 실패도 원인이 다르므로 증거에 맞춰 필요한 책임을 수정한다.

### Q38-02. 트러블슈팅 기록으로 가장 적절한 것은?

- ① 성공 화면만 남기고 원인은 생략한다.
- ② 오류 로그를 지운 사실만 기록한다.
- ③ 실패 입력·로그 → 원인 근거 → 최소 수정 → 같은 명령과 회귀 테스트 결과·배운 점
- ④ 관련 없는 기술 용어만 나열한다.

**정답:** ③

**해설:** 재현과 수정 효과를 연결하면 같은 문제를 다시 진단하고 설명할 수 있다.

### Q38-03. 본인의 트러블슈팅 사례를 추가할 때 필요한 근거는?

- ① 경험하지 않은 문제를 해결한 것처럼 적는다.
- ② 실제 실패 조건·오류·해결 커밋·회귀 테스트와 확인 결과다.
- ③ 다른 사람의 코드만 복사하고 출처·적용 결과는 생략한다.
- ④ 문제 이름만 적고 구현 근거는 남기지 않는다.

**정답:** ②

**해설:** 본인 프로젝트에서 검증 가능한 사실을 연결해야 취업 증거로 사용할 수 있다.

## 8. 심화 노트 (면접 답변 포인트)

- **5건을 관통하는 하나의 원리**: "검증·원자성·책임을 데이터 옆에 둔다." ① 상태 검증을 Entity 도메인 메서드에(중복 승인) ② 원자성을 @Transactional 에(부분 저장) ③ 응답 책임을 DTO 에(Entity 노출) ④ 로딩 시점을 명시적으로(LazyInitializationException) ⑤ 무결성을 DB 제약에(동시 가입 race). 면접에서 "이 5건의 공통 교훈은?" 에 이 한 줄로 답하면 강하다.
- **30초 압축 공식**: 증상 한 문장 → 근본 원인 한 문장 → 해결 한 문장 → 일반화된 교훈 한 문장. 예) "이미 승인된 휴가가 또 승인됐다(증상). 상태 검증이 Service if 에만 있어 다른 경로가 우회했다(원인). approve() 도메인 메서드 안으로 옮기고 테스트를 추가했다(해결). 상태 머신은 전이 규칙을 엔티티에 캡슐화해야 한다(교훈)."
- **본인 트러블슈팅 1건의 가치**: 정형화된 3건 외에 "실제로 막혔다 푼" 1건이 면접 차별화 포인트다. 사소해 보여도(설정 누락, 시드 데이터 충돌) 4단계로 정리하면 문제 해결 능력을 보여준다.
- **트러블슈팅 = 회귀 테스트와 짝**: 각 해결에 "이 버그를 재현하는 테스트를 추가했다" 를 붙이면, 같은 버그가 다시 들어오지 못한다는 점에서 설득력이 커진다(21장 통합 테스트와 연결).
