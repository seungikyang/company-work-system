## 3. 커밋 메시지 컨벤션 (PRD 3.18)

### 타입 (직접 채우기)

| 타입 | 의미 | 예시 |
|---|---|---|
| feat | 새 기능 | `feat: 휴가 승인 기능 구현` |
| ____ | 버그 수정 | `fix: 휴가 승인 상태 검증 오류 수정` |
| ____ | 리팩터링 | `refactor: EmployeeService 비즈니스 로직 분리` |
| ____ | 문서 변경 | `docs: PRD/TRD 문서 추가` |
| ____ | 테스트 코드 | `test: 휴가 승인 서비스 테스트 추가` |
| chore | 빌드/설정 | `chore: gradle 의존성 정리` |
| style | 코드 스타일 | `style: import 정리` |

### 작성 원칙

1. 제목은 50자 이내, 마침표 없음, 명령조(“구현한다” 가 아닌 “구현”).
2. body 에는 “왜” 를 적는다. “무엇” 은 diff 가 보여준다.
3. 한 커밋 = 한 가지 의도. (휴가 + 공지 + 결재를 한 커밋에 섞지 말 것)
