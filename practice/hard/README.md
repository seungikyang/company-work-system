# Hard 모드 — 최대 작성 워크북

`starter/` 가 키워드 한두 개를 채우는 **스캐폴드(쉬움)** 버전이라면, 이 `hard/` 는 코드의 **골격(제어구조·호출 형태)만 남기고 의미 있는 토큰 대부분을 비운** 최대 작성 버전이다. "내가 거의 다 쓴다" 가 목표.

## 비운 것 / 남긴 것

| 비움 (`____`) | 남김 |
|---|---|
| 타입(`Long`/`String`/엔티티명) | 제어구조(`if`/`for`/`try`) |
| 어노테이션명·속성값(`@Entity`, `unique`, `length`) | 메서드 호출 형태(`.orElseThrow(() -> ...)`) |
| enum 값·ErrorCode·상태 리터럴 | 메서드/클래스 시그니처의 괄호 골격 |
| 메서드명·Repository 이름 | 헤더 주석(`// 목표`)과 `// TODO NN` 가이드 |
| 필드명 일부 | 학습 질문(직접 답 작성 영역) |

> 답 힌트가 되는 "심화 노트" 는 hard 에서 **뺐다**. 막히면 같은 번호의 `starter/` 와 `answers.md`, `.claude/skills/spec-consistency-check/references/spec-index.md`(enum/경로/ErrorCode 정답)로 확인한다.

## 학습 루프 (권장)

1. **hard/** 에서 빈칸을 최대한 직접 채운다 (백지에 가깝게).
2. **starter/** 같은 번호로 골격·구조가 맞는지 대조한다.
3. **answers.md** 같은 장으로 "왜 그렇게 쓰는가" 를 확인한다.
4. 막혔던 칸만 다시 hard 에서 백지로 한 번 더.

## 자가 채점

각 파일 하단 `// 자가 채점` 체크리스트로 핵심 항목을 스스로 확인한다. 모든 enum·ErrorCode·API 경로·필드명은 `spec-index.md` 와 일치해야 정답이다.

## 진행 범위

코드 챕터(00–19, 21, 23–34)를 hard 로 제공한다. 워크시트형 Markdown 챕터(20, 22, 35–39)는 원래 서술 작성량이 많아 `starter/` 를 그대로 쓴다.
