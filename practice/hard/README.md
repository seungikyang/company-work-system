# Hard 모드 — 최대 작성 워크북

`starter/` 가 키워드 한두 개를 채우는 **스캐폴드(쉬움)** 버전이라면, 이 `hard/` 는 코드의 **골격(제어구조·호출 형태)만 남기고 의미 있는 토큰 대부분을 비운** 최대 작성 버전이다. "내가 거의 다 쓴다" 가 목표.

이 모드는 정답 암기보다 백지 구현 능력을 확인하기 위한 취업 워크북 단계다. 작성한 파일은 학습 연습물이며, 완료 증거는 별도 실행 프로젝트의 코드·테스트·커밋으로 남긴다.

시작할 때 연결할 FR ID와 `E-{FR ID}` 증거 ID를 파일 상단 메모나 통합 워크북에 먼저 적는다. Hard 모드에서 오래 막히면 실패 지점과 실제 오류를 기록한 뒤 Starter로 내려가며, 난이도를 낮춘 사실 자체는 실패로 보지 않는다.

처음 배우는 사람은 [초보자 기술 안내](../beginner-guide.md)와 같은 번호 Starter의 개념·사용 이유·동작 주석을 먼저 읽는다. 아래 Hard 루프는 한 번 이해한 내용을 직접 작성하며 복습하는 단계다.

## 비운 것 / 남긴 것

| 비움 (`____`) | 남김 |
|---|---|
| 타입(`Long`/`String`/엔티티명) | 제어구조(`if`/`for`/`try`) |
| 어노테이션명·속성값(`@Entity`, `unique`, `length`) | 메서드 호출 형태(`.orElseThrow(() -> ...)`) |
| enum 값·ErrorCode·상태 리터럴 | 메서드/클래스 시그니처의 괄호 골격 |
| 메서드명·Repository 이름 | 헤더 주석(`// 목표`)과 `// TODO NN` 가이드 |
| 필드명 일부 | 4지선다 학습 문제·정답·해설 |

> 답 힌트가 되는 "심화 노트" 는 hard 에서 **뺐다**. 막히면 같은 번호의 `starter/`, [정답과 해설](../answers.md), 루트의 [PRD/TRD](../../company_work_system_PRD_TRD.md)에서 enum·경로·ErrorCode를 확인한다.

## 학습 루프 (권장)

1. **hard/** 에서 빈칸을 최대한 직접 채운다 (백지에 가깝게).
2. **starter/** 같은 번호로 골격·구조가 맞는지 대조한다.
3. **answers.md** 같은 장으로 "왜 그렇게 쓰는가" 를 확인한다.
4. 같은 기능을 실행 가능한 Spring Boot 프로젝트에 구현하고 검증한다.
5. 코드 위치와 테스트 결과를 [취업 준비 통합 워크북](../job-preparation-workbook.md)에 기록한다.

Hard에서 Starter로 전환한 경우에는 막힌 개념, 확인한 힌트, 다시 직접 작성한 부분을 같은 증거 ID에 기록한다.

## 자가 채점

각 파일의 4지선다 문제는 보기 하나를 선택하고 정답·해설을 확인한다. [선택·채점 화면](../../problems.html)에서도 같은 문제를 풀 수 있다.

각 파일 하단 `// 자가 채점` 체크리스트로 핵심 항목을 스스로 확인한다. 모든 enum·ErrorCode·API 경로·필드명은 `answers.md`와 루트의 `company_work_system_PRD_TRD.md`에 정의된 기준과 일치해야 한다.

Hard 파일을 채운 것만으로 챕터가 완료되지는 않는다. 실행 프로젝트 구현, 관련 테스트 통과, 검증 명령, 커밋 또는 PR까지 연결해야 한다.

## 진행 범위

코드 챕터(00–19, 21, 23–34)를 hard 로 제공한다. 문서형 Markdown 챕터(20, 22, 35–39)는 `starter/`의 4지선다 문제와 기술 해설을 사용한다.


## 기술 설명을 먼저 읽으려면

Hard의 Java·설정 파일 35개에도 기술의 개념·사용 이유·동작 흐름을 제공합니다. 구현이 막히면 같은 챕터 Starter의 코드 옆 주석에서 입력·조건·호출·반환을 따라간 뒤 다시 풀어 보세요. 파일 읽기 순서와 조각 연결 시 확인할 부분은 [초보자 기술 안내](../beginner-guide.md)의 7~10절에서 확인합니다.
