# 취업 준비 통합 워크북

이 문서는 기술 학습을 실제 취업 결과물로 바꾸기 위한 진행 기록지입니다. 학습을 시작하기 전에 목표를 적고, 기능 하나를 끝낼 때마다 구현 증거를 갱신합니다.

## 이 문서의 역할

이 문서는 워크북 프로그램의 메인 진행판입니다. 문제를 몇 개 읽었는지가 아니라 취업에 제출할 수 있는 증거가 얼마나 쌓였는지를 기록합니다.

한 번의 학습 세션은 아래 다섯 단계로 운영합니다.

1. 오늘 끝낼 기능 또는 실패 시나리오를 하나 고릅니다.
2. 관련 문제를 직접 풀고 구현 계획을 적습니다.
3. 실행 가능한 프로젝트에 코드를 작성합니다.
4. 테스트나 빌드 명령으로 결과를 검증합니다.
5. 코드 위치, 명령 결과, 커밋, 배운 점을 이 문서에 기록합니다.

## 공통 기록 규칙

완료 체크보다 증거 링크를 먼저 기록합니다. 같은 결과물을 여러 문서에서 중복 작성하지 않고 아래 ID로 연결합니다.

| 종류 | ID 형식 | 필수 연결 |
|---|---|---|
| 기능 | `E-{FR ID}` | 코드, 테스트, 커밋·PR, 설계 이유 |
| 문서·데모 | `E-DOC-{이름}` | 공개 문서·화면 링크, 실제 확인일 |
| 트러블슈팅 | `E-TS-{번호}` | 오류, 원인, 해결 커밋, 회귀 테스트 |
| 면접 답변 | `E-INT-{번호}` | 30초 답변, 근거 코드·문서 |

예시는 `E-FR-LEAVE-005`, `E-DOC-README`, `E-TS-001`, `E-INT-001`입니다.

## 3. 시작 전 진단

각 항목을 0에서 3점으로 표시합니다.

- 0점은 설명도 구현도 어렵다는 뜻입니다.
- 1점은 예제를 보며 구현할 수 있다는 뜻입니다.
- 2점은 혼자 구현하고 테스트할 수 있다는 뜻입니다.
- 3점은 대안과 트레이드오프까지 설명할 수 있다는 뜻입니다.

## 7. 하루 학습 기록

아래 블록을 날짜별로 복사해 사용합니다.

```md
### YYYY-MM-DD

- 오늘의 목표.
- 다룬 FR ID와 챕터.
- 직접 구현한 내용.
- 실행한 검증 명령과 결과.
- 막힌 문제와 확인한 실제 오류.
- 내일 첫 번째로 할 일.
```

오늘의 목표는 한 세션 안에 검증 가능한 크기로 적습니다. “휴가 기능 완성”보다 “PENDING 휴가 승인 성공·중복 승인 실패 테스트 통과”가 좋습니다.

## 9. 포트폴리오 점검

### README 첫 화면

- [ ] 프로젝트가 해결하는 업무 문제를 두 문장 안에 설명한다.
- [ ] 기술 목록보다 주요 업무 흐름과 본인 기여가 먼저 보인다.
- [ ] 실행 방법을 새 환경에서 직접 재현했다.
- [ ] 테스트 결과와 데모 화면이 있다.
- [ ] 미구현 기능을 구현된 것처럼 표현하지 않았다.

### 코드와 Git 기록

- [ ] Controller가 Repository를 직접 호출하지 않는다.
- [ ] Entity를 API 응답으로 직접 노출하지 않는다.
- [ ] 상태 전이와 권한 실패 테스트가 있다.
- [ ] 한 커밋에 여러 기능을 섞지 않았다.
- [ ] 대표 PR에 무엇, 왜, 테스트, 영향 범위가 적혀 있다.

### 문서 일치

- [ ] README의 기능 목록과 실제 코드가 일치한다.
- [ ] ERD의 컬럼·관계와 Entity가 일치한다.
- [ ] API 명세의 경로·요청·응답과 Controller가 일치한다.
- [ ] 트러블슈팅 해결 내용과 코드·테스트가 연결된다.
