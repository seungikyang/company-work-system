# 취업 준비 통합 워크북

이 문서는 기술 학습을 실제 취업 결과물로 바꾸기 위한 진행 기록지입니다. 학습을 시작하기 전에 목표를 적고, 기능 하나를 끝낼 때마다 구현 증거를 갱신합니다.

## 3. 시작 전 진단

각 항목을 0에서 3점으로 표시합니다.

- 0점은 설명도 구현도 어렵다는 뜻입니다.
- 1점은 예제를 보며 구현할 수 있다는 뜻입니다.
- 2점은 혼자 구현하고 테스트할 수 있다는 뜻입니다.
- 3점은 대안과 트레이드오프까지 설명할 수 있다는 뜻입니다.

| 역량 | 시작 점수 | 완료 점수 | 보완할 챕터 |

| Service 비즈니스 규칙과 트랜잭션 |  |  | 08~14, 24, 28~30 |

| REST Controller와 권한 분리 |  |  | 18, 19, 25~27 |

| 테스트 |  |  | 21 |

## 4. 최종 산출물

### 실행 프로젝트

- [ ] Java 17 이상과 Spring Boot 3.x로 실행된다.
- [ ] 로컬 실행에 필요한 환경 변수와 DB 설정이 문서화되어 있다.
- [ ] 시드 계정 또는 테스트용 로그인 방법이 있다.
- [ ] 로그인, 직원·부서, 휴가, 공지, 전자결재의 핵심 흐름을 시연할 수 있다.

- [ ] 핵심 Service 단위 테스트가 있다.
- [ ] 로그인부터 승인 결과 확인까지 이어지는 통합 테스트가 있다.
- [ ] 권한 실패와 잘못된 상태 전이 테스트가 있다.
- [ ] README에 실제로 실행한 테스트 명령이 적혀 있다.

### 포트폴리오 문서

- [ ] ERD

- [ ] 트러블슈팅 최소 3건

## 7. 하루 학습 기록

아래 블록을 날짜별로 복사해 사용합니다.

```md
### YYYY-MM-DD

- 오늘의 목표.
- 다룬 FR ID와 챕터.
- 직접 구현한 내용.
- 실행한 검증 명령과 결과.
- 막힌 문제와 확인한 실제 오류.
- 내일 첫 번째로 할 일.
```

오늘의 목표는 한 세션 안에 검증 가능한 크기로 적습니다. “휴가 기능 완성”보다 “PENDING 휴가 승인 성공·중복 승인 실패 테스트 통과”가 좋습니다.

## 9. 포트폴리오 점검

### README 첫 화면

- [ ] 프로젝트가 해결하는 업무 문제를 두 문장 안에 설명한다.
- [ ] 기술 목록보다 주요 업무 흐름과 본인 기여가 먼저 보인다.
- [ ] 실행 방법을 새 환경에서 직접 재현했다.
- [ ] 테스트 결과와 데모 화면이 있다.
- [ ] 미구현 기능을 구현된 것처럼 표현하지 않았다.

### 코드와 Git 기록

- [ ] Controller가 Repository를 직접 호출하지 않는다.
- [ ] Entity를 API 응답으로 직접 노출하지 않는다.
- [ ] 상태 전이와 권한 실패 테스트가 있다.
- [ ] 한 커밋에 여러 기능을 섞지 않았다.
- [ ] 대표 PR에 무엇, 왜, 테스트, 영향 범위가 적혀 있다.

### 문서 일치

- [ ] README의 기능 목록과 실제 코드가 일치한다.
- [ ] ERD의 컬럼·관계와 Entity가 일치한다.
- [ ] API 명세의 경로·요청·응답과 Controller가 일치한다.
- [ ] 트러블슈팅 해결 내용과 코드·테스트가 연결된다.
